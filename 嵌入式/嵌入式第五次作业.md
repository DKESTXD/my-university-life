##  1  问题描述

做一个控制系统，输入是温度/光敏传感器，输出是步进/直流电机。

设定一个初始值（以当前温度/亮度为参考），如果传感器温度/亮度超过初始值，则电机正转；如果低于设定值，则电机反转；当前值和初始值差异越大，则电机转速越快

## 2 问题分析

本次作业我的传感器选择光敏传感器，输出为步进电机。

预期结果可以描述为：光照光敏电阻变化，在传感器上输出模拟量，经过adc模数转换器转换为数字量，数字量再映射成电压值，再根据传感器的电路反推出光敏电阻值，由光敏电阻值映射到光照强度；将光照强度显示在lcd屏幕上，lcd共显示两个数据，一个为基准光照强度，一个为当前光照强度；通过按下按键K1可以将基准光照强度更新为当前的光照强度；电机选择为步进电机，限制其转速在一个区间[0,max]内，当光照强度小于基准值反转，大于基准值正转。将当前光照强度与基准值的差线性映射到速度区间上，实现偏离基准值越多转速越快，更详细的分配策略见后续。

分析问题的要求，可以将其分解为各个小模块：光敏传感器获取光照强度，ADC模数转换，LCD屏幕显示，按键控制，步进电机控制。

u16 Get_ADC_Value(u8 ch,u8 times)
{
	//times 是获取的次数，依照此次数取平均值
	u32 temp_val=0;
	u8 t;
	ADC_RegularChannelConfig(ADC1, ch, 1, ADC_SampleTime_239Cycles5);

	{
		ADC_SoftwareStartConvCmd(ADC1, ENABLE);
		while(!ADC_GetFlagStatus(ADC1, ADC_FLAG_EOC ));

		delay_ms(5);
	}
	return temp_val/times;
}

{

    LCD1602_RS_RESET();
    LCD1602_RW_RESET();//写指令

### 3.4 电机

#### 3.4.1 电机的选择

为什么不选择直流电机呢，如果选择直流电机，用pwm波即可调转速，这样将与基准值的差映射为占空比即可完成差值与转速的对应。但是非常致命的一点是，直流电机不能控制正反转（至少我在仅用这块板子的资源的基础上实现不了）。

直流电机只有两个输入端口，其中一个固定为5V横流源，另外一个为pwm波输入控制转速。而使其反转的方法本质上只能让另一个端口输入5V，这一个输入pwm波。比较典型的解决方案有**H桥，双继电器**等等。对于H桥，我没有；继电器我只有一个，而且我还需要双头的杜邦线来实现并联。开发板上关于电机的驱动有两块芯片——ULN2003和TC1508S，理论上TC1508S是可以支持直流电机反转的，**但是开发板只引出了一半的引脚**，导致不能实现了。此外我还想过，能否两端都输入pwm波，令其中一路的占空比为100%，能否看作直流恒压。理论上是可行的，但是实际上，即使其占空比是100%，其本质上也是个谐波，含有谐波分量，因此直流电机不可行。

#### 3.4.2 步进电机

实验箱配备的为四线四相电机，用TC1508S芯片驱动，原理为依次给四端的电磁铁供电，使电机可以转动，根据步进角的不同可以分成不同拍，如四拍和八拍。

| A+   | OA--IA | PA12 |
| ---- | ------ | ---- |
| A-   | OB--IB | PA0  |
| B+   | OC--IC | PA5  |
| B-   | OD--ID | PA7  |

**转动原理如下，使用的是四拍**

```c
u8 reverse[4] = {0x03,0x09,0x0c,0x06}; //反转
u8 forward[4]= {0x03,0x06,0x0c,0x09}; // 正转
void SetMotor(unsigned char InputData)
{
	if(InputData == 0x03)
	{
		GPIO_SetBits(GPIOA,GPIO_Pin_12);
		GPIO_ResetBits(GPIOA,GPIO_Pin_0);
		GPIO_SetBits(GPIOA,GPIO_Pin_5);
		GPIO_SetBits(GPIOA,GPIO_Pin_7);
	}
	else if(InputData == 0x09)
	{
		GPIO_SetBits(GPIOA,GPIO_Pin_12);
		GPIO_SetBits(GPIOA,GPIO_Pin_0);
		GPIO_SetBits(GPIOA,GPIO_Pin_5);
		GPIO_ResetBits(GPIOA,GPIO_Pin_7);
	}
	else if(InputData == 0x0c)
	{
		GPIO_ResetBits(GPIOA,GPIO_Pin_12);
		GPIO_SetBits(GPIOA,GPIO_Pin_0);
		GPIO_SetBits(GPIOA,GPIO_Pin_5);
		GPIO_SetBits(GPIOA,GPIO_Pin_7);
	}
	else if(InputData == 0x06)
	{	
		GPIO_SetBits(GPIOA,GPIO_Pin_12);
		GPIO_SetBits(GPIOA,GPIO_Pin_0);
		GPIO_ResetBits(GPIOA,GPIO_Pin_5);
		GPIO_SetBits(GPIOA,GPIO_Pin_7);
	}
	else if(InputData == 0x00)
	{	
		GPIO_ResetBits(GPIOA,GPIO_Pin_12);
		GPIO_ResetBits(GPIOA,GPIO_Pin_0);
		GPIO_ResetBits(GPIOA,GPIO_Pin_5);
		GPIO_ResetBits(GPIOA,GPIO_Pin_7);
	}
}

void motor_circle(int n, int direction, int delay)
{
    int i, j;
		if(n==0){SetMotor(0x00);}	
		else{
    for(i = 0; i < n ; i++)
    {
		for(j = 0; j < 4; j++)
		{
			if(1 == direction)
			{
				SetMotor(forward[j]);
			}
			else
			{
				SetMotor(reverse[j]);
			}
			delay_ms(delay > 2 ? delay : 2);
		}
    }
	}
}	
```

#### 3.4.3 步进电机的转速控制

步进电机的程序在主程序中运行时，如果用motor_circle()函数一直加大圈数，会发现其转速一段时间后不会再提高，在圈数较小时，电机转完所需的时间远小于主循环中其他数据处理的时间；当提高到一定数量后，电机转动成为了主要消耗时间的任务，这就导致**在若干个while循环中，转过圈数的总和除以时间越来越趋近于其转一圈所用的固定时间，即到达了最大值**，不能再增，再增加徒增时间消耗。因此为了实验现象明显，我们将电机的转速设定在一个小区间内，最大值约为一个while循环中120圈。

### 3.5 主程序文件

#### 3.5.1 差值与转速的映射

在实验过程中，我们发现光照强度是非常不线性的一个量，日常情况下为400lux左右，在光照强度较小时，从完全黑暗的0到400lux的变化速度远小于从400lux升高的速度。而且光照强度基准值较难达到一千，因此做出以下映射策略；

当光照强度在基准值上下不超过30lux范围内，电机不转动；

当光照强度小于基准值-30lux：

​	direction=-1，反转

​	如果基准值小于1030(1000+30)，speed=max_speed*(lux_based-lux)/(lux_based-30)+1;//其中+1是防止取整后为0

​	如果基准值大于1030：

​		当lux大于基准值-1030，speed=(lux_based-lux)/1000*max_speed+1;

​		当lux小于基准值-1030，speed=max_speed，达到最大值。

当光照强度大于基准值+30lux：

​	direction=1，正转

​	当lux小于基准值+1030，speed=(lux-lux_based)/1000*max_speed+1;

​	当lux大于基准值+1030，speed=max_speed，达到最大值。

上述的speed值对应的是圈数，因此会做取整处理。

#### 3.5.2 各个模块的组合

如果单纯的将电机控制函数motor_circle（speed，direction，2）放在while的开头，那么当圈数开始上升的时候，电机的转动与数据的处理是非常割裂的，电机转动会有明显的卡顿感，为了解决这个问题，有三个方案。

##### 3.5.2.1 中断处理实现伪多线程

确定电机转动与数据处理的优先级，将电机转动改为中断事件，每个一段时间触发一次，更改中断的间隔时长可以实现电机的转速控制。事实上当间隔时长非常小的时候，还是会影响数据处理的速度。再加上这个功能有些复杂，没有完成。

##### 3.5.2.2 pwm波模拟步进电机输入

我们理想的情况是电机可以脱离主循环，自行转动，而主循环只需要控制电机开闭以及调节其参数即可。在不支持多线程的stm32f103c8芯片上，唯一能够实现类似功能的是pwm波，自初始化开始便不受主循环控制，一直在输出，而且还可以调节其参数。

| 1    | 1    | 0    | 1    |

##### 3.5.2.3 非阻塞式编程

通俗将，便是将每个while循环里总共需要的圈数细分均匀分布到代码中，与数据处理的代码融合，虽然并没有完全解决问题，但是现象改善了许多。

此外，还有一点，这样设置便是将数据处理与转机速度关联，当速度慢，一个while只转一圈，时间短，因此光照强度更新速度也更快，导致不同转速下光照强度更新速度不均匀，为了均衡一下，做了补偿设计，即加一个while的计数变量i，当速度过小时，每当i%50==0，即每间隔50个while循环更新一次光照强度，速度快时则不触发这样虽不能保证更新速度完全一致，但是也大致均衡。

## 4 还可以改进的点

### 4.1 更准确地光照强度与阻值的转换公式

本实验用到的I--R的公式仅在光照强度低的时候大致吻合，且其推导过程与参考值都是估计来的，虽然定性上满足，但是定量上仍然存在较大误差。

### 4.2 更丝滑的速度过渡与电机

因为main函数中用到了将电机转动分成了各个小块的非阻塞编程，再加上速度是靠整数——圈数来衡量的，这就导致了速度的变化不丝滑，每一个小的speed单位变化，对应的是整个循环过程中总圈数加了12个单位，变化不丝滑。

还有就是上述提到的中断与pwm波方法，应该都能实现电机转动与主程序循环分离，但是受限于实力，没有完成，导致最终成品电机仍存在一点卡顿，能解决卡顿问题将非常完美。
